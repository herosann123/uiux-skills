# UI 布局骨架 Skill · 决策辅助（刻意低约束）

> **设计哲学**：布局是最依赖内容的层。本技能只守 5 条底线（§1），
> 其余全部是**决策问题**（§2）和**可替换的起点配方**（PATTERNS.md，明确标注"起点不是答案"）。
> 如果按本技能做出来所有页面长一个样，那是执行错误。

---

## 1. 硬约束（仅 5 条，违反即改；此外一切皆可谈）

1. **无横向溢出**：任何视口下 `scrollWidth ≤ clientWidth`（实测，非目测）
2. **行长 45–75ch**：正文段落；超出就分栏或加宽边距
3. **触控目标 ≥ 44×44px**：手机/平板上所有可点元素
4. **间距出自同一 scale**：允许自选 scale（§3 给三档），但不允许随机值混用
5. **视觉层级 ≤ 4 层**：一屏内字号权重档位超过 4 层 = 没有层级

## 2. 三个决策问题（先问内容,再定骨架）

1. **信息优先级**：用户第一眼必须看到什么？第二眼呢？——答案决定主列宽度与首屏构图
2. **阅读动线**：内容是线性的（文章/教程→单列）还是并列的（商品/功能→网格）还是探索式的（画廊/叙事→自由流）？
3. **内容密度**：一屏 3 个元素还是 30 个？——决定间距 scale 档位与栅格列数

**这三个问题的答案不同，同一"落地页"的正确骨架就不同。配方只是把常见答案组合预先画了出来。**

## 3. 间距 scale（三档，按内容密度选一档并全站统一）

| 档位 | 基数 | 阶梯 | 适合 |
|------|------|------|------|
| tight 紧凑 | 4px | 4/8/12/16/24/32/48 | 仪表盘、工具、数据密集 |
| normal 标准 | 8px | 8/16/24/32/48/64/96 | 大多数营销页、官网 |
| loose 宽松 | 12px | 12/24/36/48/72/96/144 | 高端品牌、画廊、留白型 |

代码 token 见 PATTERNS.md §A。**换档是自由决策，混用两个档是违规。**

## 4. 断点策略（内容驱动,而非设备驱动）

- **首选内容断点**：容器内容放不下时才换行/换列——用容器查询或 `min()`/`clamp()`/`auto-fit`
- **媒体查询只做两件事**：导航形态切换、多栏→单栏的翻转点
- 断点值从内容出发（试出内容挤压的临界宽度），不照抄 768/1024
- 手机优先写基础样式，`min-width` 向上增强

## 5. 页面类型 → 骨架起点（PATTERNS.md §C,均标注可替换）

| 页面类型 | 骨架起点 | 何时不用 |
|---------|---------|---------|
| 营销落地页 | 单列叙事 + 全宽 Hero + 交替节奏段 | 内容并列比较时改网格 |
| 内容/阅读页 | 单列 65ch + 目录侧栏(≥1024) | 图文集改错落网格 |
| 表单/流程页 | 窄单列(≤480px 居中)+ 分步 | 仪表盘型表单改分区 |
| 仪表盘 | 顶栏+侧栏+卡片网格(auto-fit) | 阅读型内容混入时降密度 |
| 展示/画廊 | 自由错落或横向叙事 | 有强线性叙事时不用 |
| 移动 App 式 | 底部 Tab + 全屏栈 | 内容需要大屏对照时不用 |

## 6. 反模式（少而准）

- ❌ 万能三栏：三个等宽卡片不代表内容天然等重
- ❌ 固定像素全宽容器（`width: 1200px`）→ 用 `max-width + 百分比`
- ❌ 手机上硬塞桌面栅格 → 先单列，内容说话再分栏
- ❌ 间距随机值（13px、27px、41px）→ 出自同一 scale
- ❌ 为了对称硬凑空块 → 留白不对称是正常的
- ❌ 断点照抄设备表不看内容 → 溢出和挤压才是断点依据

## 7. 输出契约

沿用 `../ui-interaction-skill/SKILL.md` §11.1 四层分级：
必须满足 = §1 五条底线；推荐 = 所选 scale + 骨架起点及理由；可选 = 备选骨架；禁止 = §6。
