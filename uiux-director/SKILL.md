# UIUX 总控 · 技能组路由

> 技能组：`ui-layout-skill`(骨架) · `ui-visual-skill`(质感) · `ui-interaction-skill`(动效) ·
> `ui-component-skill`(组件与状态) · `ui-verify-skill`(实测验收)。
> 本技能只做**判断、排序、交接**，不代替任何子技能产出。

## 0. 三条纪律（先读这个）

1. **按缺口路由，不跑流程**：只补当前任务缺的环节。已有页面改个颜色，不需要动效和验收全场走一遍。
2. **小任务直接做**：预计改动 ≤1 个文件、不涉及设计决策的，跳过所有技能直接执行。
3. **轻量交接**：跨技能交接用一段内联的状态记录（任务/已定决策/产物路径/下一步），不造文档体系。

## 1. 缺口路由表

| 用户在要什么 | 路由 | 说明 |
|-------------|------|------|
| 从零做一个页面/应用 | **layout 骨架 → visual 定调 → (component 细节) → interaction 动效 → verify 验收** | 顺序建议而非强制；每步产物直接进入下一步 |
| "不够高级 / 有点土 / 像模板" | **visual**（可能带 interaction） | 先问还是先看截图，遵循 interaction §11.3 盲评包 |
| "加点动效 / 要那种高级感交互" | **interaction** | 查其 §4 映射表；"再加动效"先过其 §11.2 减法表 |
| "手机上不好使 / 卡 / 错位" | **interaction 移动端铁律 + verify** | 先 verify 定位证据，再按铁律修 |
| "帮我看看这页面行不行" | **verify**（含盲评纪律） | 无截图不做视觉评分；输出四态结论 |
| "做个表单 / 弹窗 / 组件" | **component**（骨架缺就先 layout） | 组件先列状态矩阵再写样式 |
| 页面空着难看 / 加载体验差 | **component 的页面状态流** | loading/empty/error/success 四态 |
| 单一小修改 | **不走路由,直接做** | 完成后建议一句"要不要 verify"即可 |

## 2. 子技能清单（同级目录,按实际安装路径引用）

| 技能 | 负责层 | 关键入口 |
|------|--------|---------|
| `../ui-layout-skill/SKILL.md` | 骨架：栅格/间距/断点/层级 | §2 三个骨架决策问题 + 页面类型起点配方 |
| `../ui-visual-skill/SKILL.md` | 质感：字体/配色 | §2 气质→配方决策表 |

## 3. 组织一次多环节任务

1. **问缺口**：目标是什么？已有什么？设备/用户是谁？有截图吗？——只问会影响路由的，已知信息不重复问。
2. **排顺序**：按路由表排出本任务需要的环节和顺序；明确说"哪些环节这次跳过、为什么"。
3. **逐环节执行**：读对应子技能 SKILL.md（按需再读其 PATTERNS.md），产出直接写进代码或简短文档。
4. **交接记录**（超过 2 个环节时才写，内联即可）：

```markdown
<!-- uiux-state -->
任务：xx
已定：气质=编辑暖夜；断点=内容驱动；动效=②+⑧（减法已过）
产物：index.html · tokens 在 :root
下一步：verify(手机 390 + 桌面 1280)
未做：组件状态矩阵（无表单）
```

5. **收尾**：涉及实现的环节结束后建议 verify；verify 的四态结论是交付的前置，不放行未验证项。

## 4. 权限边界

- 总控可以读代码、写代码、跑浏览器测试——与 uiux-design-suite 那种"只读方法论"不同，本组是**干活的技能组**；但每个子技能内部的纪律（盲评、减法、四态）依然约束执行。
- 多环节任务中，先给路由计划再动手；用户只要分析时，停在分析。
- 区分"用户已确认 / 推断 / 假设"；未验证项不得写成已完成。

## 5. 完成条件

用户能明确说出：做了什么、跳过了什么及原因、下一步是什么、哪些项还没验证。
